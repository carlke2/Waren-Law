# WAREN Law website: Version 1

**Tag:** `v1.0.0`
**Prepared:** 3 November 2026, for the client review on 5 November
**Status:** release candidate for client review. Not on the live domain, and not yet deployed to a server.

## What V1 contains

**Public site, with the firm's existing content served from the database**
- Home, About, Our Team, 10 advocate profiles, Our Partners
- Areas of Expertise and 8 practice areas, with the two debt pages merged into one
- Insights: 32 articles, category pages, pagination and an RSS feed at `/feed/`
- Webinars: index and 3 webinars, shown as recording or past
- Contact, with 3 offices, click-to-load maps, WhatsApp and booking
- Search, Privacy Policy, Terms and Disclaimer, Cookie Policy, and styled error pages

**Working features**
- Contact form: stores each enquiry, emails the firm once SMTP is set, blocks bots with a honeypot and rate limit, and deletes enquiries after 12 months
- Cookie consent: Google and Meta tags load only after a visitor accepts
- Practice areas linked to their advocates and articles, and a team filter by practice area
- All 101 current URLs checked: each works at the same address or redirects once
- Search-engine data: titles, descriptions, canonicals, social cards, structured data, sitemap and robots rules

**Foundations:** Next.js frontend, NestJS backend, PostgreSQL on Supabase, shared validation, automated tests, Docker and Nginx configuration, and a deployment runbook.

## Search engines

V1 stays out of search results: `SITE_INDEXABLE=false` adds `noindex` everywhere and blocks crawlers. This changes only at launch.

## Known gaps

**Not yet verified**
- Docker images, Compose and Nginx haven't been run, because the build machine has no Docker. First use on a server may need adjustments (`docs/runbook.md`).
- Email delivery hasn't been tested with a real mail server, because no SMTP details are set. Until they are, enquiries are stored but nobody is emailed, so **someone must check the database or SMTP must be set before real visitors use the form**.
- Google's Rich Results Test needs a public address.
- Real phones and screen readers haven't been tested.
- The home page's load time should be rechecked on staging behind Nginx caching (decision 0012). Locally it scores 89–96, with LCP from 2.5 s to 3.6 s, slowest on a cold image cache.
- Short Supabase connection failures were seen from the build machine, mostly DNS failures after idle periods. Timeouts and one automatic retry now cover them, and the final run had no server errors, but this should be watched on the server.
- GitHub CI results couldn't be seen from the build machine.
